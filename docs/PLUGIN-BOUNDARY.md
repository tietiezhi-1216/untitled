# 宿主与插件的边界

宿主管安装、校验、更新、配置持久化、通用窗口与槽位、系统授权、快捷键注册和事件调度。插件拥有该功能的界面、指令、会话、资源、数据清理和业务策略。源码归属、编译归属与更新渠道是不同的边界。

## 四个插件的归属

| 插件 | 插件拥有 | 宿主提供 |
| --- | --- | --- |
| `global-shortcuts` | 清单里的命令编排、绑定范围和默认模板 | 打开应用、网址、运行系统快捷指令、打开主面板等通用动作 |
| `screenshot` | 采集和编辑工作流、贴图、历史维护、暂停截图快捷键、KaTeX 和 WebP 工具 | 系统授权、注册和触发快捷键、打开宿主面板、转发显式复制事件 |
| `peripheral-sharing` | 配对、连接、键鼠与音频会话、剪贴板同步、虚拟麦克风驱动、切换与紧急键策略 | 绑定插件身份的权限入口、通用按键所有权与路由事件 |
| `doubao-speech-input` | 录音、识别、听写 HUD、插入/复制策略、历史库、按住与 Esc 的会话逻辑 | 系统授权、派发已绑定的动作、受限的会话临时快捷键、偏好目录 |

后三个原生插件的实现已分别归到自己的 `Plugins/<slug>/Sources/`。应用内资源路径、系统权限身份、应用支持目录和用户配置格式保持兼容。

`UntitledPluginSDK` 提供通用数据模型；`UntitledHost` 只依赖 SDK。三个独立原生 Swift target 使用 SDK 和宿主接口，不依赖彼此。位于 `Sources/Untitled/App/` 的 `UntitledComposition` 是唯一同时引用全部原生 target 的生产组合根。SwiftPM 和 Xcode 都从同一入口静态链接该产品，产出一个签名应用；这是编译期依赖约束，不是运行时沙盒。旧 IME 部件只用于独立输入法目标与测试，主应用不再链接它。

截图和键鼠共享通过各自 `Tools/stage-app-resources.sh` 提供原生资源；命令行和 Xcode 共用构建入口。仅执行受审查的仓库构建脚本，安装 ZIP 不参与该过程。

## 内置模块如何接入

`Sources/Untitled/App/PluginComposition.swift` 是内置模块的组合入口。模块通过 `PluginUIRegistry` 注册 UI，通过 `PluginRuntimeRegistry` 登记动作、手势和生命周期。`PluginStore` 验证已安装、已启用、已保存的绑定和清单声明，再把动作交给登记的模块；未登记的原生动作不能安装。系统权限依然通过按插件身份绑定的客户端检查。升级先写入已验证的配置，成功后才通知原模块结束或恢复会话。插件卸载负责自己的数据，通用壳不猜测其文件命名。

录屏启动在创建控制器前检查权限；停止已在运行的录屏不要求重新授权。升级若移除截图能力或权限，结束受影响的工作并保留输出。截图只发出成功的图片复制事件，不创建共享服务；共享只交给已启用的活跃会话，再由其原有配对和剪贴板授权判断是否转发。宿主统一注册、分派和清理快捷键；截图暂停、语音按住/临时 Esc、共享释放后切换和事件过滤由各插件定义。

改名的语音 fork 按自己的插件 ID、动作和绑定注册临时 Esc。共享 fork 使用各自的偏好和钥匙串条目，不继承内置配对或恢复意图；同进程最多一个活跃共享会话。卸载截图保留已有媒体、历史和贴图数据；卸载共享停止会话并清除恢复意图，配对资料可通过「解除配对」主动清除；卸载语音按原行为清除该插件偏好和识别历史。

旧动作 ID、清单、快捷键、应用身份与历史数据迁移规则保留。动作标识继续用同样的 JSON 字符串编码；动作名和图标由模块提供，运行时注册表拒绝未注册标识。打开应用、打开网址、运行系统快捷指令、显示主面板是所有声明式插件可使用的宿主动作。原生代码仍是**已信任的同进程内置模块**，不把权限接口当作对恶意代码的沙盒。

## 哪些改动能独立更新

ZIP 仍只接纳 `manifest.json`、`README.md` 和 `LICENSE`。0.13.51 起，清单的 `styles` 除了原有界面和动作配置之外，可以携带注册模块支持的数据样式。宿主只校验体积、类型及是否有注册的提供者；样式版本、范围及解释由插件自己决定。

语音插件先支持 [`doubao.hud` v1](../Plugins/doubao-speech-input/README.md#独立更新浮条样式)。同一个宿主可在不重启、不重绑的情况下安装两种样式 ZIP，并在下次听写显示新尺寸、颜色和动效参数。无样式的老清单继续使用默认外观；不合法的 ZIP 不覆盖旧配置，也不停止当前会话。

原生代码仍由 Swift Package 和 Xcode 编译到宿主。这套机制不能让旧宿主获得它不认识的渲染或业务实现，也不执行 ZIP 内的原生代码。要独立分发任意原生实现，需要另行落地版本化的运行接口和明确的可安装包信任模型。建议验证签名和包身份、使用独立且受系统约束的进程、经由按插件身份和授权范围校验的接口访问系统能力；设计取消、撤权、崩溃、升级回退、旧数据兼容，再逐个迁移内置模块。不从普通 ZIP 动态加载代码，不放松 Hardened Runtime 或系统权限，也不把子进程本身描述成权限隔离。
