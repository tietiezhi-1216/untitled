# Untitled 开发说明

项目只面向 macOS。Swift Package 与 Xcode 共用同一个静态组合产品；应用、package、应用 target、scheme 与可执行文件统一为 `Untitled`，Xcode 工程为 `Untitled.xcodeproj`。插件贡献见 [CONTRIBUTING](../CONTRIBUTING.md)。


### 原生界面与 Liquid Glass

主窗口采用 `hiddenTitleBar` 与全尺寸内容，不显示独立的标题条或工具栏，保留原生红黄绿按钮。左侧顶部预留 60 pt 窗口按钮区域，按钮距左侧与顶部各 18 pt，按钮间距 8 pt，搜索框从预留区下方开始；原生按钮宿主仅覆盖左侧，避免挡住正文控件。按钮保留 AppKit 原生对象及激活状态：未激活窗口显示灰色，激活后由系统显示红黄绿，不用自绘圆点模拟。顶部空白区和页面头部可拖动窗口。

侧边栏固定为 224 pt，始终显示且不可拖动调整；主窗口仍支持正常调整尺寸。右侧内容统一使用 28 pt 水平边距。安装、搜索、添加操作等控件在各页面上方保持可见。

插件商店采用 App Store 风格的左侧搜索与导航，右侧为两列展示区。页面标题与筛选菜单同排，已安装插件从侧栏「我的插件」打开。下方每个插件用图标、名称、作者和胶囊形获取按钮组成条目头部，再展示 1.6:1 宣传大图。列间距 26 pt，行间距 34 pt，窗口变宽仍保持两列；最小 880 pt 主窗口下也保留双列。图片与文案声明来自通用注册数据，界面不按插件 ID 编排。宣传图全部通过 Codex 内置图像工具生成，来源与提示词见 Resources/StoreArtwork/README.md。

窗口采用低透色的中性材质：深色模式以石墨黑为底，浅色模式使用对应的浅灰色，侧栏与正文只有轻微明暗差。原生 `underWindowBackground` 背景保留少量桌面层次，避免壁纸颜色大幅染色。玻璃效果集中在搜索与操作控件；Xcode 26+（或包含 macOS 26+ SDK 的命令行工具）构建时使用官方 `glassEffect`、`.glass` / `.glassProminent`，配合收敛的圆角、选中态细边缘和蓝色重点操作。开启系统“减少透明度”或增加对比度时提高背景遮罩的不透明度。macOS 14–15 运行时保留兼容样式。

设计依据：[Apple Liquid Glass 采用指南](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)、[材质规范](https://developer.apple.com/design/human-interface-guidelines/materials)。

### 软件本体更新

设置中的“软件更新”与插件商店独立，显示运行版本/构建号、手动检查正式发布版、更新说明与兼容本体包的下载页入口。没有自动轮询、后台下载或自替换安装；发布来源、资源预算及限制见 [软件更新](HOST-UPDATES.md)。

### 原生能力

主窗口侧栏的「原生能力」集中提供文件定位与系统分享、纯文本剪贴板、本地通知，以及已接入的插件动作和待接入能力。宿主工具放在 `Runtime/HostNativeCapabilities.swift`，权限由 `SystemPermissionProvider` 注册。插件功能继续从自己的工作区执行。接入状态和授权规则见 [权限与执行规范](PERMISSIONS.md)。

### 构建

```bash
swift build
swift test --no-parallel
python3 scripts/prepare-plugin-resources.py --check
./scripts/build-app.sh release
python3 scripts/package-plugins.py --tag v0.13.0
# 仅在 Release 资产实际发布后，追加 --write-catalog 更新在线商店
```

AppKit 窗口焦点测试请显式串行运行 `swift test --no-parallel`，避免多个界面测试互相抢夺 key window。若 Swift 6.4 命令行工具报告找不到 `TestingMacros`，可显式传入随工具链安装的插件路径（完整 Xcode 通常无需此选项）：

```bash
swift test --no-parallel \
  -Xswiftc -load-plugin-library \
  -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing/libTestingMacros.dylib
```

应用打包以 `xcrun --sdk macosx` 选出的 SDK 为准，最低构建 SDK 为 26，本机工具链为 27.0。需要更新 SDK 时请更新或切换 Xcode / Command Line Tools，无需更改最低运行版本 macOS 14.0。`build-app.sh` 在签名前校验主程序、WebP helper 和随包音频驱动各架构的 Mach-O SDK 与最低版本；CI 同时校验 Xcode 产物，仍使用 `macos-26` 运行器上的工具链。

构建结果位于 `dist/debug/Untitled.app` 或 `dist/release/Untitled.app`，使用当前 Mac 的架构。命令行与 Xcode 均不启用 App Sandbox，保留系统隐私授权。图标由 `scripts/build-icon.sh` 从选定的裂变原图生成，随应用打包。

内置插件展示信息来自 `Sources/Untitled/Resources/BundledPlugins.json`，Swift Package、命令行应用包与 Xcode 都包含同一资源。修改插件清单后运行 `python3 scripts/prepare-plugin-resources.py`；图像生成与内嵌方式见 [插件协议](../Plugins/README.md#商店展示图标与文档0120)。构建脚本与 CI 会检查资源是否同步。这份资源不安装插件、不改变已发布 ZIP、商店版本与 SHA-256。

**语音草稿与写入**（0.13.34+）：`DoubaoDictationController` 分开显示假设和提交定稿；`DictationHUD` 仅投影最新文字，`DictationFinalInserting` 没有写草稿的接口。0.13.33 的独立 IMK 目标保留作隔离回归，发行包不再嵌入，不安装、注册或选择输入源。0.13.38+ 的写入目标在 `finish()` 返回非空定稿时解析一次；录音阶段不读编辑器，直接插入无法确认才通过注入的剪贴板出口复制，过期回调或取消不复制。测试用模拟 ASR、离屏 AppKit 文本视图、私有命名剪贴板和临时历史库；不要把对自建编辑器的验证当成所有第三方输入框的验收。

**流光听写胶囊**（0.13.50+）：启动仍显示九颗随实际音量起伏的彩点；第一份草稿触发约 340ms 的展开及声柱淡出，之后卸载音量视图。88 × 38 pt 初始胶囊以同一底部中心展开，高度增到 48 pt，宽度按 TextKit 实际单行宽度分档增长至 296 pt。中途缩短的假设不会让胶囊收缩。文字以相同字号逐字显现，满宽后保留滚动的单行尾部。定稿、剪贴板、焦点和识别流程不变，无需重装插件。

后台只在展开的听写胶囊内绘制五道共享径向渐变，不采样桌面、不分配额外模糊缓冲。一个浮条任务协调有界形变和约 30 Hz 色光采样；定稿、降低透明度、减少动态效果或关闭后不持续绘制色光；字形显现仍由原有短任务驱动。Mac16,10 / macOS 27.0.1 优化编译，2×／296 × 48 pt 合成背景 2,100 帧，中位数 1.161 ms、P95 2.600 ms；不是整窗合成、连续峰值或功耗测量。96 项相关 Swift Package 测试通过（可选联网测试按默认跳过），覆盖真实离屏绘制的颜色漂移、圆角裁切、深浅色、宽度重定向、停止动画、单行字幕与焦点不变。未使用真实麦克风，未测桌面材质合成、长时功耗或完整 Xcode 编译。

**旧版液态折光听写声柱**（0.13.49）：用随实际音量平滑起落的包络驱动两组错峰声柱、流动的色彩与半透明反光。持续发声时不冻结，响音渐进收顶，停顿时柔和收回到静态圆点。macOS 26+ 保留原生 Liquid Glass，旧系统保留浮层材质；降低透明度时使用原有不透明底板，不叠加透色光晕。保留 9／31 个固定位置、字幕布局和定稿流程，无需重新安装插件。

资源预算：每帧最多 31 根声柱和 3 道共享矢量渐变，沿用一个刷新任务（间隔至少 17ms）和最多 24 个音量包络片段，不添加音频缓存、整窗模糊、采集或权限。音量回调断开 280ms 即开始回落；静音稳定、脱离窗口和减弱动态效果时停钟。Mac16,10 / 16 GiB / macOS 27.0.1 上，优化编译的同一组 2× 离屏波形，各 2,100 帧，绘制用时中位数／P95 从 0.505／1.371 ms 变为 0.736／2.057 ms；这是合成输入的波形绘制快照，不是整窗合成、连续峰值或长时功耗测量。

四组语音相关 Swift Package 串行回归通过（94 项通过、可选联网测试按默认跳过），覆盖恒定音量下的实际像素换色、响音上限和丢失回调后连续回落、浅／深色、减少透明度、静音停钟与合成 PCM。未使用真实麦克风，未测不同桌面背景下的玻璃合成、GPU 峰值、长时功耗或完整 Xcode 构建。

公式贴图使用随应用打包的 [KaTeX](../Plugins/screenshot/Resources/KaTeX/LICENSE)。静态 WebP 与 WebP 动图编码使用 [libwebp](../Plugins/screenshot/Tools/WebPEncoder/LICENSE)：`build-app.sh` 会构建并签名随包的 `img2webp`，首次构建下载固定版本源包并验证 SHA-256，用户运行发行版无需安装 Homebrew 或编码工具。相关许可保留在资源与工具目录。仅运行 Swift Package 可开发基本能力；完整发行功能应使用 `build-app.sh` 生成应用包。

本地智能擦除模型通过截图设置显式下载，下载量为 187 MiB，独立存储在应用支持目录；不包含在主应用或插件 ZIP 内。采用 [LaMa Core ML](https://huggingface.co/mlboydaisuke/LaMa-CoreML)，遵循 Apache-2.0，安装器固定模型版本并校验 SHA-256。图像推理在本机完成，无需云端账号。

为了在后续更新中保留 macOS 对应用身份的识别，建议使用固定的代码签名证书。先将证书及配对私钥导入本机钥匙串，再查看可用身份：

```bash
security find-identity -v -p codesigning
printf '%s\n' '证书的40位SHA-1' > .signing-identity
./scripts/build-app.sh release
```

`.signing-identity` 是仅用于本机的配置，不提交到仓库，也不包含私钥或密码。`scripts/run.sh` 同样读取此配置。配置了证书后，构建会启用 Hardened Runtime、摄像头与麦克风访问 entitlement 和安全时间戳，并在签名校验成功后替换旧构建；证书或私钥不可用时会直接报错，不会退回临时签名。

也可以用环境变量 `UNTITLED_SIGNING_IDENTITY` 覆盖本机配置。未配置身份时保留临时签名，适用于 CI 和首次试用；显式设置为 `-` 也可使用临时签名。临时签名在代码变化后可能无法沿用先前的系统授权。从临时签名切换为证书签名时，需要重新确认系统权限。公开分发仍需使用 Developer ID Application 证书并完成 Apple 公证；此脚本不自动提交公证。

如果切换签名后，系统设置中开关已开启，应用却仍显示未授权，旧记录可能仍绑定临时签名的代码哈希。可先退出应用，仅重置本应用对应的权限，例如 `tccutil reset ScreenCapture com.untitled.app`，再打开当前签名版本，从应用的权限管理重新请求并由用户允许；系统提示时选择退出并重新打开。辅助功能和输入监控对应 `Accessibility`、`ListenEvent`，仅在相应权限出现同样问题时分别处理。无需重置其他软件或所有权限。[Apple 的代码签名说明](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)介绍了系统如何用指定要求识别更新后的应用。

Xcode 开发入口：

```bash
open Untitled.xcodeproj
```

选择 `Untitled` scheme 和 `My Mac` 后按 `⌘R`。Xcode Target 与命令行构建统一采用非 App Sandbox 配置，保留 Hardened Runtime 与摄像头/麦克风 entitlement；系统受保护操作仍需用户授权。`.signing-identity` 只作用于终端构建，Xcode 中需另外配置同一签名身份。正式分发需配置自己的签名和公证。

SwiftPM 与 Xcode 使用同一应用入口和静态 `UntitledComposition` 产品，Xcode 不重新列举宿主与插件的 Swift 文件。新增原生源码放在所属 target 的目录内。SDK、宿主和三个插件的依赖图、实验 IME（只供独立目标和测试）可用 `python3 scripts/check-module-boundaries.py` 验证；完整 Xcode 编译仍需要 Xcode。两条应用打包路径都调用 `scripts/stage-plugin-resources.sh`，只运行仓库中的插件资产构建钩子，不执行安装包中的文件。GitHub Actions 验证模块图、测试、插件打包和 Xcode 构建。

发布完成后，可额外执行真实 GitHub 下载与安装检查：

```bash
UNTITLED_NETWORK_TEST=1 swift test --filter downloadFromPublishedGitHubCatalog
```

### 本机安装与回退

修改宿主原生代码或随宿主编译的插件功能，或者用户明确要求更新宿主时，通过相关验证后默认更新当前 Mac 的 `/Applications/Untitled.app`。纯文档和仅改声明式插件包不触发宿主替换；用户明确要求不安装或只预览时保留现有安装。`build-app.sh` 仍只打包到 `dist/`，`run.sh` 仍用于开发预览；两者成功都不等于已安装。这项交付仅在用户的 Mac 上执行，不在 CI 执行，也不触发公开发布或驱动安装。

1. 确认构建包含目标提交，核对架构、`com.untitled.app`、显示版本和构建号，不无意降级。核对 `/Applications/Untitled.app` 的实际绝对路径，不经过符号链接覆盖其他副本。对候选包执行签名校验（`codesign --verify --deep --strict`）；替换证书签名版时，验证候选包仍满足旧版的指定要求。无法沿用旧签名或要改为临时签名时，先告知可能需要重授权限并取得明确同意。
2. 正常退出运行中的 Untitled，包括测试副本。若录制、保存或确认流程尚未结束，不强退，也不在运行中覆盖。使用完整旧包与已验证的候选包做原子交换或等效的可回退替换；把旧包保存在「应用程序」之外的唯一备份目录。不改动插件配置、历史、钥匙串或系统授权；无法安全替换则保留原安装，不绕过权限或系统保护。
3. 从 `/Applications/Untitled.app` 启动，核对实际进程的可执行文件路径、版本和构建号，确认不是预览副本。签名校验、替换或启动失败时保留或恢复旧包并说明原因。记录实际安装的版本、源码提交、签名类型、备份位置与未完成的功能验收；安装与启动成功不能代替实际截图、录音等验收。

## 数据与兼容标识

当前开发版使用 `com.untitled.app` 作为 Bundle ID、偏好与应用支持目录命名空间；内置插件使用 `com.untitled.*`，Keychain 与音频驱动也使用新身份。历史数据迁移、冲突备份、系统重新授权及双机升级要求见 [IDENTITY-MIGRATION.md](IDENTITY-MIGRATION.md)。应用支持目录不在仓库内。普通 `swift run` 不会生成图标和 helper，完整体验使用 `scripts/run.sh`。品牌资源见 [BRANDING.md](BRANDING.md)。

## 验证范围
