# 本机复制与跨机截图剪贴板 · Untitled 0.12.23 / build 63

## 问题与范围

- 0.12.21 的剪贴板协议只接受 UTF-8 文本，Untitled 截图则复制 PNG。即使两个开关都打开，旧版也不会送图。
- 现场用 Paseo 读取了两端状态与系统日志类别，未读取剪贴板内容。取样时键鼠已连接、两端剪贴板开关都是关闭；Untitled 的剪贴板实现没有粘贴监听、按需网络数据提供者或进度窗。80 的 `pboard` 日志有系统远端剪贴板取数失败。迹象指向 macOS 通用剪贴板，但不能把用户看到的具体弹窗确定归因到某一进程。

## 使用

在两端「键鼠共享」中打开「剪贴板共享」。在 Untitled 截图中完成框选或标注并点击「复制」或按 `⌘C`，本机可照常粘贴；对端收到后在支持图片的应用按 `⌘V`。不是按下粘贴才传输，不把未到达的图片占位符放进剪贴板，不拦截或重放粘贴按键。只框选、保存或取消不会传输。未同步或过大的图片只留本机；两端不需要重配对。关闭剪贴板共享、退出或断线会撤销许可；不改变系统 Handoff、TCC、键鼠或截图快捷键。

## 实现与边界

- Untitled 复制的是已经编码好的 PNG，不是懒加载数据。通过 `currentHostOnly` 把新产物或收到的内容作为本机条目写入，不把这些条目交给 Apple 通用剪贴板再次传输。截图历史与剪贴板复用最终 PNG，不为传输重新编码；其它导出格式和可编辑原图按原设置保存。
- 镜像截图由成功的本机截图复制直接触发；不轮询或读取未知图片，没有屏幕捕获、云服务、额外传输文件或日志。旧对端仍可同步文本。其他应用和系统复制的图片、文件不在范围内；第三方复制触发的 macOS 通用剪贴板不受此改动控制。
- 双方各自开启且能力匹配时，图片复用原端口建立**独立的 TLS-PSK 连接**，以两条 TLS 会话和双方当前授权绑定认证。仅在图片连接就绪后发送，优先由本机正常输出。每端最多一张已发待回执、一张等待发送（新复制替换等待项）、一张接收校验；上限为 32 MiB 和 2400 万像素。图片处理不在键鼠流排队，不引入新的持续轮询；网络仍共用物理链路。对端完成接收、校验，且未失权、没有更新剪贴板时才写入；版本与授权变化阻止迟到图片覆盖。失败只结束图片连接，文本和控制连接不受影响。

## 验证

- 在 0.12.22 的冻结截图源码上叠加本修复，**223 项 / 13 组**串行回归通过。包含带标注 PNG 的本机提交顺序、复制失败不发送、4K PNG 的双向加密回环、图片和控制帧并行、输入边界、错序保护、撤销及旧版文本协议。测试用合成图、私有命名剪贴板或 fake 适配器；没有读取用户剪贴板，也未代用户执行真实截图或粘贴。
- SwiftPM Release 构建、工程 plist、内置资源一致性及签名检查通过。没有完整 Xcode 构建环境，也没有测量真机端到端耗时、长时资源峰值或第三方应用的通用剪贴板行为。
