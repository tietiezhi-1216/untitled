# 外设共享 0.12.16：边缘归还与移动连续性

## 现场证据

在两台 0.12.15 / build 55 Mac 上，用户观察到切回原设备时，另一台边缘留下光标，并且过屏会停顿。Paseo 只读状态显示 TLS 和布局同步仍有效。设备 A 一次成功的后台所有权确认约 39 ms；设备 B 收到输入后，一次停放在约 209 ms 后安全退出，没有清理错误或 watchdog 过期。旧版日志没有区分窗口未命中与标记事件未通过，不能只凭这些数字判定哪个步骤失败。该次 五个 ICMP 样本约 5.8–23.7 ms，不是交接或渲染耗时。

## 实现

- 等已提交的接收位移通过监听，并读回最终系统指针，不再为停放重复 warp。读回超出 24 ms 的等待预算则安全结束本次归还，不放宽持有租约时的 0.5 pt 漂移检查。
- 已停放的目标在准备阶段保持隐藏，收到同次交接的提交才在隐藏状态定位到入口、退面板并显示。后备的普通接收路径仍在提交时定位。
- 带标记的同位置事件使用独立、不抑制本地事件的合成源。命中与回执分别记录；回执直接唤醒等待任务，不再以 4 ms 轮询回执。仍需有效的 tap、租约和所有权确认，不因 API 返回成功跳过门槛。
- 两台新端可通过同次交接的 TCP 输入序号补回返回途中未被旧屏使用的相对位移。历史上限 256 项，补偿每轴不超过 128 pt；序号失效或间隔内有按键、点击或滚轮则不补偿。新字段仅在双方协商且有返回位置时随正常归还发送，不读取或保存键鼠轨迹。旧端仍沿用原握手、权限和返回行为。
- 正常边缘返回定位在入口内侧，不靠统一延时防止来回弹跳；急停、权限和异常清理规则不变。

## 验证边界

138 项相关串行回归（共享、布局、快捷键及应用生命周期）通过，覆盖回执超时分段、停放前延迟读回和拒绝、隐藏下一直等到提交、正常均衡清理及两端回环的位移补偿。测试使用 fake 光标/事件与隔离 TLS 回环，不触发真机接管。工程和 Info.plist 校验通过；未执行完整 Xcode target 构建。

只有接力期间才产生确认等待或暂存位移，不加空闲轮询、常驻进程或联网服务。双机同构建的视觉、接力延迟及长期资源用量仍需实测；不能用单元测试或连通状态宣称残留箭头、卡顿已消失。
