# 外设共享 0.12.5：安全恢复验证

宿主 0.12.5 / build 44，插件 1.4.4，最低宿主 0.12.5。无协议格式、权限、配对身份或布局迁移变更。

## 修复范围

- 事件监听因 timeout 停用时，旧路径先同步报告失败并销毁 tap，后续重新启用无效。现在先撤销交接、归还控制和清理已投递输入，再确认现有用户意图、授权和监听权限；重新启用监听后等待 100ms，再重新采样物理按住状态、允许后续新动作发起交接。一个可取消任务，每 60 秒最多三次；不恢复旧控制、旧输入或光标租约。
- `tapDisabledByUserInput`、权限撤销、恢复失败或预算耗尽仍安全暂停。不会把系统用户输入停用当成普通超时，也不会绕过授权或保护条件。
- 正常归还后的停放光标失去前台时，清理成功即可留在本机，保留健康监听。正在控制、staged、清理失败等情况仍走原有安全暂停。
- 意外断线只由保存了既有手动地址的主动端重试，间隔三秒，最长两分钟；手动断开、停止、锁屏和睡眠取消。Bonjour 选择不会重新拨打旧手动地址。重连仅恢复认证连接与布局，不重新启用已暂停输入或音频。
- 心跳和重试使用单调时钟；聚合诊断增加消息年龄、最大主循环间隔、重连次数及监听恢复阶段/计数，不记录按键、用户文本或音频。

这修复了安全退出后的恢复路径，不代表已经确定所有操作系统停用、前台变化或心跳间隔的最初诱因。

新增回归覆盖恢复预算、timeout 与 user-input 区别、恢复取消/重复/失败、权限撤销、停放与活动控制的区别、清理失败、双端交接撤销，以及有界单侧重连且不重新启用暂停输入。

另执行资源同步检查、差异检查和 CI workflow 语法检查。PR 的完整 CI、签名构建和本机交付另按各自实际结果记录；本文件中的单元测试不替代这些检查。
