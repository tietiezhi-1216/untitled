# 键鼠共享：保连接、恢复输入与断线重连

参考 Oink 0.3.6（`c15f275`）的分层恢复策略，独立实现；保留 Untitled 的 TLS-PSK、布局、原交接协议及本机光标监护期限。

- **输入短暂失效，不关共享。** 撤销旧接力并归还本机光标；对端释放已按下的键／按钮。系统临时关闭事件监听时，在已授权且非安全输入的前提下先尝试重新启用原监听，必要时重建并重新采样物理状态。还在恢复时暂不接力；恢复后可直接进行一次新跨屏，不重放故障期间的输入。TLS、布局和现有剪贴板 grant 保持不变。
- **链路失效才重拨。** 已认证会话的原拨号端记住地址／Bonjour 端点及对端 UUID；另一端继续监听，避免两端同时拨号。链路丢失后优先立即重试，之后重试间隔退避至 0.5 / 1 / 2 / 4 / 5 秒，任何时刻最多一次拨号。保留既有 1 秒网络心跳和 5 秒失活判定，改用单调时钟。未完成首次认证的旧地址提示仍使用原有 120 秒启动窗口；已认证的目标不受该窗口限制。地址变化且原端点已不可达时，可在有本地键鼠的一侧显式选新端点。
- **配对与数据边界不变。** 每条新链路重新验证 TLS-PSK 并核对所记住的设备 UUID，重新协商布局及剪贴板 grant。断线期间输入和剪贴板不排队、不补发。旧端继续用已有协议；运行期自动拨号由支持恢复的一端负责，不要求旧端理解新消息类型。
- **用户可以真正停下。** 停止、锁屏、睡眠及解除配对不会自动重新开共享。主动断开/取消重连拒绝对端后台重连，也取消本机重试；用户再次显式选择连接才绕过该保留状态。老端不能标记一次远端显式拨号时，可以在本机重新选设备。真实权限撤销、安全输入或清理失败继续安全暂停，不自动绕过。`⌃⌥⌘Esc` 仍立即结束当前接力。

恢复复用共享会话的既有计时器：新增状态仅有各一个重试时刻、一个拨号候选目标和一次活跃尝试，不引入常驻额外计时器或故障输入缓存。未测两台物理屏上的恢复耗时和视觉连续性。
