# 外设共享 0.12.18：直接交接与离边停放

复现与 Oink 0.3.6 的源码差异见 [链路对照](SHARING-OINK-CODE-REVIEW.md)。这不是 Oink 协议兼容层，未移植其 GPL 源码。

- **去掉可避免的交接等待。** 监听和租约有效，且原生隐藏、解除关联、取得光标区域、提交显示更新及系统的隐藏状态均满足时，本机无需透明面板回执即可交接。双端额外协商直接入口能力；源端发带布局版本与接力 ID 的入口，随后才发位移。目标端仍检查共享授权、权限、输入抢回及同一布局。缺少原生证据保留完整面板确认；旧端保留原协议顺序。
- **处理离开设备的旧光标。** 停放前保护已投递位移的顺序。成功取得原生隐藏后，仅在菜单栏、Dock 保留区或配置的触发角等需要时将离开的接收端光标停放到同一屏内侧。若看见系统隐藏状态消失，每份租约至多平衡修复一次；未能确认则归还控制。面板回退增加光标矩形及鼠标刷新，急停始终可用。
- **归还后不放行旧位移。** 在短抑制间隔可用的系统上回位前请求该间隔，过滤回位完成之前排队的物理移动。仍保留 0.12.16 已有的有界归还位移补偿与回放门；不补发按键或点击。状态记录原生隐藏证据与确认阶段，不记录输入位置、内容或轨迹。

## 验证

152 项相关串行测试 / 8 组通过，含 TLS 回环下不等待面板的进入及归还、旧端顺序兼容、布局失配及权限拒绝、原生证据不足的回退、离边几何、回位旧移动、隐藏失败和清理。这些测试用注入的光标/事件后端，不操纵生产桌面。已通过工程 plist 和资源一致性检查；没有完整 Xcode 构建验证。

对 80（macOS 27.0.1）和 81（macOS 26.6.2）的只读检查确认能解析相关光标状态、区域及回位符号，**不证明主程序取得区域或实际显示器隐藏了箭头**。不增加空闲查询；现有维护循环只在持有原生租约时至多每 100 ms 核查一次可见状态，失败修复最多一次；面板和回放预算不增加。未测：原生停放所需时间、双机实际跨屏延迟与可见性、多轮回收和长期资源用量。

## 本机交付

80 已正常退出 0.12.17，并从 `/Applications/Untitled.app` 启动 **0.12.18 / build 58**。签名指定要求未变、深层严格验签通过，主程序与 `dist/release/Untitled.app` 一致，保留旧版回退归档。未更改配对和系统权限。初次交付时 81 仍为 0.12.15；两端曾在混版状态下重连。

## 81 同版部署

再次收到残留箭头反馈时，81（0.12.15）最近一次停放约 **210 ms** 后未确认所有权，清理恢复了光标显示；这与旧屏残留吻合，但不证明每次残留都来自此路径。80 最近一次原生冻结约 **0.58 ms**，只是本机 API/状态耗时，不是实际渲染或端到端延迟。

通过 Paseo 正常退出并将 81 更新到 **0.12.18 / build 58**，保留原应用与配置的私有回退备份。两端严格验签通过，主程序 SHA-256 相同；80 未重装。由 80 通过原保存的 Tailscale 地址发起连接；复查两端键鼠开启、监听就绪、布局同步，无待恢复资源。未改配对、权限或驱动，也未代用户触发跨屏。同版重连后的输入计数仍为零，尚无新一轮停放的可见性证据，需由用户实际观察。
